# docs/ — המסמכים הקאנוניים

זהו "מקור האמת" של הפרויקט. הקוד נגזר מהמסמכים האלה — לא להפך.

## למה זה קיים

AI לא זוכר הכול לנצח (בעיית חלון הקונטקסט). במקום להילחם בזה,
שומרים את האמת של הפרויקט במסמכים קצרים וממוקדים, וכל סוכן מקבל
רק את הפיסה שהוא צריך. כך טעות לא מתגלגלת הלאה.

## המבנה

```
docs/
├── 00-product/        # ה"למה" — מה בונים ולמי
│   └── PRD.md
├── 01-architecture/   # המבנה הכולל — מודולים, נתונים, גבולות
│   └── architecture.md
├── 02-modules/        # ה"איך" — אפיון מפורט לכל מודול
│   ├── _TEMPLATE.md
│   └── <module>.md
└── 03-decisions/      # ADR — למה בחרנו X ולא Y
    ├── _TEMPLATE.md
    └── <NNN>-<title>.md
```

## כללים

1. **מסמך לפני קוד.** אין קוד למשהו שאין לו אפיון.
2. **מסמך אחד = נושא אחד.** קצר וממוקד עדיף על מסמך-ענק.
3. **שינוי החלטה = עדכון מסמך + ADR.** לא משנים קוד בשקט.
4. הקבצים `_TEMPLATE.md` הם תבניות — מעתיקים, לא עורכים אותם.

## סדר העבודה

רעיון → `02-modules/<module>.md` (אפיון) → אישור `architect` →
פירוק למשימות → קוד → ביקורת → בדיקות → בלם → commit.
